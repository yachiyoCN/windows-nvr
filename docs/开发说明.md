# 开发说明

本项目包含 Windows 桌面端、内置 Web 前端和 Android 客户端。桌面端版本为 1.4.1，Android 客户端版本为 1.5.1（versionCode 9）。

## 目录约定

| 路径 | 内容 |
| --- | --- |
| `desktop/src/main/java/` | 桌面端 Java 源码 |
| `desktop/src/main/resources/` | 打包进 JAR 的图标与 Web 资源 |
| `desktop/native/` | 录像目录校验组件源码 |
| `desktop/assets/` | Windows 应用图标 |
| `android/` | Android Gradle 工程 |
| `scripts/` | 构建和发布辅助脚本 |
| `third_party/` | 第三方来源、校验值和许可证 |

运行数据位于程序目录的 `config/` 和 `data/`。这些目录以及签名文件、证书私钥、连接导出文件和录像不属于源码。

## Windows 桌面端

### 构建环境

- Windows x64
- JDK 21 或更高版本，包含 `javac`、`jar`、`jlink` 和 `jpackage`
- Windows .NET Framework C# 编译器
- FFmpeg、FFprobe 和 FFplay，用于生成完整便携版

可通过 `JAVA_HOME` 或 `-JdkPath` 指定 JDK。

### 编译

仅编译 Java 程序和目录校验组件：

```powershell
.\build.ps1 -CompileOnly
```

输出文件位于 `build/home-monitor.jar` 和 `build/StorageGuard.exe`。

生成完整便携版：

```powershell
.\build.ps1 `
  -DependencyDirectory 'D:\recorder-dependencies' `
  -IncludePersonDetection
```

默认输出目录为 `dist/录像机/`。目标目录已存在时脚本会停止，使用 `-Destination` 指定新的输出目录。`-BuildDirectory` 可指定中间产物目录，`-RuntimeImage` 可复用包含 `jdk.httpserver` 的 Java 运行环境。

桌面程序通过 `jpackage` 生成启动器，并使用 `jlink` 创建专用运行环境。Web 资源从 `desktop/src/main/resources/cn/homewatch/web/` 打包进 JAR，不依赖 Node.js、CDN 或独立 Web 服务。

### 媒体与人员检测依赖

在依赖目录中放置以下 FFmpeg 文件：

- `ffmpeg.exe`
- `ffprobe.exe`
- `ffplay.exe`

人员检测依赖可通过固定地址和 SHA-256 校验下载：

```powershell
.\scripts\download-person-dependencies.ps1
```

脚本下载 YOLOX-tiny 模型和 ONNX Runtime Java 1.20.0 到 `tools/person-detection/`。使用 `-IncludePersonDetection` 时，缺少依赖会导致构建失败。来源、版本和许可证见 [第三方组件](../third_party/README.md)。

### 应用图标

图标源文件位于 `desktop/assets/`。修改图标后执行：

```powershell
.\scripts\generate-app-icon.ps1 -JdkPath $env:JAVA_HOME
```

该脚本同时更新 Windows ICO 和桌面端资源 PNG。

## Android 客户端

Android 工程使用 Java 17、compileSdk 35、minSdk 26 和 Android Gradle Plugin 8.7.3。Android Studio 可直接打开 `android/`。

使用已安装的 Android SDK 和 JDK 手动构建：

```powershell
.\android\build-apk.ps1 `
  -SdkRoot 'D:\Android\Sdk' `
  -JdkRoot 'D:\Java\jdk-21'
```

默认输出为 `android/build/manual/录像机.apk`。未提供签名参数时生成开发包，不能覆盖正式签名的已安装版本。

正式签名使用环境变量传递口令：

```powershell
.\android\build-apk.ps1 `
  -SdkRoot $sdkPath `
  -JdkRoot $jdkPath `
  -Keystore $keystorePath `
  -KeyAlias recorder `
  -StorePasswordEnv RECORDER_STORE_PASSWORD `
  -KeyPasswordEnv RECORDER_KEY_PASSWORD
```

同一包名的后续版本必须沿用原签名，才能覆盖安装并保留客户端数据。密钥库、口令文件和签名口令不得加入源码仓库。

## Windows 更新包

更新包生成器从最终 JAR、源码文档、完整安装依赖和正式 APK 创建白名单包，并生成逐文件 SHA-256 清单：

```powershell
.\scripts\create-update-package.ps1 `
  -JarPath '.\build\home-monitor.jar' `
  -SourceDirectory '.' `
  -InstalledProgramDirectory 'D:\recorder' `
  -ApkPath 'D:\release\录像机.apk' `
  -OutputDirectory 'D:\recorder-update'
```

输出目录必须为空，并且不能与源码或安装目录嵌套。更新包不包含 `config/`、`data/`、录像、截图、证书私钥或签名文件。

生成包中的 `更新.cmd` 是面向使用者的双击更新入口；它与更新工具、校验清单一起生成。源码中的 `scripts/install-update.ps1` 是打包模板，应运行生成包中的安装器。

在解压后的更新包中执行完整性检查：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File '.\更新工具\安装更新.ps1' `
  -TargetDirectory 'D:\recorder' `
  -ValidateOnly
```

更新安装器会请求程序正常退出、备份现有发布文件、完成替换并重新启动。配置、用户、设备、安全数据和录像目录不会被更新包覆盖。

## 发布检查

发布前至少完成以下检查：

1. 执行 `build.ps1 -CompileOnly`，确认桌面端可编译。
2. 校验 Android debug 或 release APK 的包名、版本号和签名。
3. 检查 `git status`，确认没有配置、凭据、录像、日志和构建产物。
4. 核对 [API 文档](API.md) 与 [OpenAPI 定义](openapi.yaml) 是否一致。
5. 随发布包保留根目录 `LICENSE`、`NOTICE` 中的项目链接及所用第三方组件的许可和来源资料。桌面构建会将根文件嵌入 JAR 的 `META-INF/` 并复制到便携包根目录；Android 两种构建方式均将其嵌入 APK 的 `assets/`，更新包也会复制根文件。
6. 分发 FFmpeg 二进制前，按 [第三方组件](../third_party/README.md) 核对其对应源码、构建配置和外部库的分发要求；保留 ONNX Runtime JAR 内的 `ThirdPartyNotices.txt` 和 OpenJDK 运行环境的 `legal/`。
